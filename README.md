# 行迹 Xingji

Android 本地航班记录应用，同时包含桌面版和可自行部署的 Cloudflare 版本源码。

## Android 安装

最新版本 **1.4.1**：[直接下载 APK](https://github.com/cagfriend/xingji/releases/download/android-v1.4.1/xingji-1.4.1.apk)，或打开 [Releases 发布页](https://github.com/cagfriend/xingji/releases/latest)。

Android 7.0 及以上可安装。已有行迹 App 可直接覆盖安装，使用相同包名和签名，保留本机记录与 API 设置。不要先卸载或清除数据。

应用不预置个人行程或 API Key；用户可在设置中填写自己的 API。支持自然语言／票据截图识别、确认后保存、航班号与日期去重、航线地图、历史统计、飞机资料与照片、JSON 导入导出。安装包内置全球概览级离线地图，不等同于街道导航地图。

1.4.1 修复底部提示被导航栏遮挡的问题，提示现在显示在导航栏上方；横竖屏和系统安全区布局检查通过。其他界面保持不变。

源码构建方法见 [Android 说明](mobile/README.md)。仓库不包含个人数据、部署私密配置、签名私钥或本机工具链。重新构建时需要自行配置工具链和签名；自行签名的包不能直接覆盖官方发布包。

## 桌面版

以下为原桌面项目说明。

# 行迹 · 本地行程管理

本机运行的中文行程管理应用，无数据库或加密。使用 Node.js 22 或更新版本，界面在浏览器中打开。地图组件已随项目打包，地图底图需要联网加载。

Windows 启动器会优先使用系统的 Node.js，未安装时尝试使用这台电脑上的 Codex 自带运行环境；不打包或下载运行环境。

## 启动

Windows 双击 `启动行迹.cmd`，保持启动窗口打开。浏览器若先打开而未连接成功，稍后刷新。也可在项目目录执行 `node server.mjs`，访问 http://127.0.0.1:4317 。关闭启动窗口即可停止服务。端口占用时可通过 `TRIP_PORT` 环境变量修改端口，并在浏览器打开对应地址。

## 使用

1. 输入自然语言，或选择／拖入票据照片、预订单截图（PNG、JPEG、WebP，每张最大 8 MB，最多 5 张，总计 24 MB）。
2. 选择 AI API 识别。未接入 API 时，可选择本地规则体验简单文字识别，或手动填写。本地规则不是 AI，不支持 OCR／图片，复杂内容必须使用 API。
3. 在确认窗口核对所有字段，补齐缺失信息、修改错误信息、移除重复项目。AI 结果不会直接存储。
4. 点击“确认并保存”。航班必须提供航班号与预计起飞日期。仅支持航班，不识别或保存火车、酒店、停留等信息。

支持多段航班、修改、移除、关键词搜索与 JSON 导出：

- 航班：航班号、起降机场和对应航站楼、预计／实际起降日期和时间、机型、飞机注册号、票价（包含币种）、座位号。

预计起降时刻与实际时刻独立记录，尚未发生或票据没有的信息留空，不用预计值补实际值。日期是时间的一部分，用于跨日行程及去重。机场当地日期可能因时区及国际日期变更线出现倒序，本版本不自动转换时区，也不将当地时间简单比较后拒绝保存。

## 行程地图

主界面左侧地图约占三分之二。已保存航班根据机场坐标定位，相同机场合并成一个节点。每条有方向的航线以弧线示意，线中间显示航班号。点击单条航线直接查看详情；同一方向同一航线有多趟时，先展开航班号列表，再选择一趟查看。点击任一机场圆点会分别列出从该机场出发及到达该机场的已保存航班，并可继续打开单趟详情。右侧搜索同步过滤地图。地图支持滚轮缩放、拖动、缩放按钮和一键显示全部航线。路线端点、机场标记和文本标签都由同一地图投影定位，不会因容器尺寸变化而错位。

地图打开时从 OpenStreetMap 加载当前视野所需的街道级瓦片，随缩放显示更多细节。已看过的瓦片另存于当前浏览器的本机缓存，下次打开相同区域优先使用缓存；按服务端返回的有效期更新，断网时可在允许的过期容错期限内继续显示部分已看过的区域。清除浏览器站点数据、换浏览器或缓存被浏览器回收后需重新联网加载。只缓存实际查看的瓦片，不预下载整片区域。机场坐标由项目内置的全球机场坐标和常见中文机场别名提供，不会因看图而向地图服务提交行程文本、航班号或 API 密钥。机场按整个机场的地点定位，航站楼仍在航班详情中显示；弧线是可视化示意，并非实际航路或实时轨迹。

AI 识别航班后，会先识别具体机场与 IATA／ICAO 代码，再使用本机内置的 OurAirports 目录校验并在确认窗口补上三字 IATA 代码。城市名称有多个机场时不会猜测，系统会提示你在确认窗口核对；识别与目录校验都发生在保存之前。不同地方出现相同名称、名称无法精确匹配，或坐标目录未覆盖时，不会按城市中心猜测坐标：地图下方会出现「待定位」，可输入该地点的 WGS-84 经纬度并保存在本机 `data/places.json`。这些数据源为社区数据，不保证测绘级精度，重要行程请自行核对并校准。

地图资料来源与许可：

- [OurAirports 全球机场坐标](https://ourairports.com/data/)：Public Domain。
- [TMC_Dataset 中文机场名称对照](https://github.com/Timeon1/TMC_Dataset)：MIT，© 2024 YanWei。原库许可可在其仓库查看；本项目只分发从其名称表派生的别名。
- [中国高铁模拟项目的站点数据](https://github.com/linroger/china-hsr-simulation)：MIT © 2026 Roger Lin；其部分站点来自社区站点 CSV 与 OpenStreetMap，涉及 [ODbL](https://www.openstreetmap.org/copyright)，本项目在地图上保留 OpenStreetMap 署名。
- [OpenStreetMap 标准地图瓦片](https://operations.osmfoundation.org/policies/tiles/)：按需联网加载，遵循返回的缓存有效期，不进行预下载，并在地图右下角持续显示署名。
- [Leaflet 1.9.4](https://leafletjs.com/download.html)：MIT，JavaScript/CSS 文件在 `dist/vendor/` 本地提供，无需运行时加载外部脚本。

`scripts/build-map-data.mjs` 可从 OurAirports 最新公开目录重新生成本地点坐标目录；运行脚本时需要联网。旧版国家轮廓文件仍保留供数据重建参考，但当前地图不再使用它。

## 航司标识

航班号会按照前两位 IATA 航司代码自动匹配本机内置标识。现已覆盖中国大陆主要航司，以及港澳台、日本、韩国的主要客运航司；未收录的航司会保留彩色代码标识，不影响保存或显示航班。标识文件仅随本机项目使用，不会向第三方请求或上传行程数据。

## 接入 API

点击“API 设置”，填写基础地址（例如 `https://你的服务/v1`）或完整的 `.../chat/completions` 地址、密钥与模型名称。使用完整地址时不会重复拼接路径。基础地址不自动补 `/v1`，请按照服务商说明填写。

当前适配器支持 Chat Completions 兼容接口：POST JSON，`Authorization: Bearer <key>`，`messages` 含文字及 `image_url` 的 base64 图片，返回 `choices[0].message.content`。图片识别需要支持视觉的模型。未配置、不支持图片、返回格式无效或超时（90 秒），都会显示错误，不会创建行程。为了兼容不同服务商，未强制发送 `response_format`；通过系统提示要求 JSON，并在本地校验。

待你提供 API 说明后，可对 `server.mjs` 中识别请求与响应适配部分调整。其他接口形式（例如独立 OCR、不同鉴权或 Responses）目前不直接支持。

形式化结果：

```json
{
  "trips": [{
    "type": "flight",
    "code": "CA1831",
    "date": "2026-10-12",
    "departure": "北京首都",
    "departureTerminal": "T3",
    "arrival": "上海虹桥",
    "arrivalTerminal": "T2",
    "departureTime": "08:00",
    "arrivalDate": "2026-10-12",
    "arrivalTime": "10:15",
    "actualDepartureDate": "",
    "actualDepartureTime": "",
    "actualArrivalDate": "",
    "actualArrivalTime": "",
    "aircraftType": "",
    "registration": "",
    "ticketPrice": "680 CNY",
    "seat": "12A"
  }],
  "warnings": []
}
```

`type` 固定为 `flight`。航班的 `date/departureTime` 及 `arrivalDate/arrivalTime` 表示预计起降时刻，`actual*` 表示实际时刻。未知字段为空字符串，不应猜测；日期使用机场当地出发日期，不是下单日期；时间使用当地 24 小时制，不自动转换时区。识别缺失字段可以进入确认窗口，但缺失必填项不能保存。机型、航站楼、注册号不能从航班号凭空推断；仅进行输入内容的提取，不查询实时航班数据。

## 本地数据和重复规则

- `data/trips.json`：已确认行程；`data/config.json`：API 配置。首次保存时生成对应文件。
- `data/places.json`：用户手动校准的地点坐标。不会发送至 DeepSeek 或地图服务。
- `data/aircraft-cache.json`：按飞机注册号缓存 Airport-Data 的机型、序列号等资料，以及 Planespotters 的照片缩略图链接和摄影者署名。首次新增含注册号的航班时会后台查询；打开航班卡片时刷新照片。注册号匹配会忽略连字符、空格和全角字符，因此 `BHLM` 与 `B-HLM` 共用缓存。
- 航班去重键：规范化航班号 + 预计起飞日期。航班使用预计起飞日期，不因实际延误跨日改变去重键。忽略大小写、全角字符、空格和连字符。例如 `ca 1831` 与 `CA1831` 同日视为重复。不同出发日期可保存；同日相同航班号会拒绝重复。
- 前端即时提醒，服务端最终校验，覆盖已保存数据、本批次及修改冲突。保存串行执行，写入通过临时文件替换，避免并发造成丢失。
- 每次修改前保留原文件为 `.bak`，仅保留最近一次版本。恢复前先关闭应用，再自行备份当前文件，将 `.bak` 复制为对应 `.json`。
- 源图片和原始输入不作为附件永久保存，仅保存确认后的结构化字段。重新刷新页面会清空未保存的草稿。
- 导出包含个人行程信息，不含 API 密钥。导出是备份用，本版本不提供 JSON 导入界面。

## 隐私范围

服务只监听本机 `127.0.0.1`。不使用运行时 CDN 或外部字体，没有遥测。打开地图时，浏览器会向 OpenStreetMap 请求当前视野的瓦片。新增含飞机注册号的航班或打开航班详情时，应用会向 Airport-Data / Planespotters 查询注册号相关资料；详情中的照片由 Planespotters 在线提供，图片会直接从其图片服务器加载，并链接回原照片页、显示摄影者署名。上述站点会看到被查询的飞机注册号和网络请求信息，但不会收到完整行程或 API 密钥。仅点击 AI 识别时才发送本次输入至指定 API，并受该服务的数据政策约束；因此“本地运行”不等于“完全离线”。可接入本机兼容视觉模型服务用于离线识别。

按照要求，数据和密钥均为明文，不提供加密或账号认证。不要共享 `data` 文件夹，不要将端口转发到公网。本机其他程序或能使用你的浏览器的人可能读取这些数据。

# Cloudflare 在线版

新增单人在线部署入口，保留原本本地启动方式。在线版使用 Workers + D1，默认通过专属随机密码登录，不依赖 Zero Trust；也保留 Cloudflare Access 模式。API Key 仅保存在 Worker Secrets。

- 部署与迁移说明：[cloud/DEPLOY.md](cloud/DEPLOY.md)
- 本地测试：`pnpm test`
- 云端打包检查：`pnpm run cloud:check`
- Cloudflare 运行环境测试：`pnpm run cloud:runtime-test`（先执行打包检查）
- 密码登录真实运行环境测试：`pnpm run cloud:password-test`（先执行打包检查）
- 生成不含密钥的迁移快照：`pnpm run cloud:snapshot`

`data/` 与在线 D1 不会自动同步。迁移须在已登录的在线版设置中确认，或由本人授权运行迁移工具；未配置完整的登录保护时，在线服务拒绝访问。
